# 指令：流量-转化断层诊断（沉默黑洞）

## 目标 (Goal)

跨数据源关联商品维度的流量数据与转化数据，识别三类"沉默黑洞"——有曝光无点击、有点击无商机、有商机无成交——精准定位每个黑洞的断层原因，输出可直接行动的修复优先级清单。这是人类最难发现、AI最擅长完成的诊断类型。

## 适用范围 (Scope)

- 智能体：管理-经营复盘官、运营-Listing优化官、运营-P4P推广官
- 工作流：流量转化提升工作流（跨节点关联诊断）

## 是否定时执行 (Schedule)

是 —— 每月 15 日 09:00 执行（月中执行，与月初TOP榜形成前后对照）。

## 前置 (Prerequisites)

- 插件【国际站生意助手】ACTIVE；具备数据参谋商品效果查看权限
- 数据参谋 T-2 延迟，统计截止执行日前 2 天
- 本指令需关联两个数据维度：商品效果数据（曝光/点击/CTR）+ 询盘/商机数据（商机数/询盘数）
  若两个维度数据均可取 → 执行完整版诊断
  若仅能取一个维度 → 执行单维度诊断并注明数据缺口
- ⚠️ Token 控制前置声明：
  - 本指令核心产出是"黑洞清单"，不是数据报表，禁止平铺所有商品数据
  - 正常转化商品不展开，只计数
  - 每个黑洞商品输出限定为"1行数据 + 1句断层原因（≤20字）+ 1条修复建议（≤20字）"
  - 三类黑洞各输出上限10条，超出只计数
  - 执行前必须输出预检行

## 最终使用的指令 (Instruction)

```
请调用【国际站生意助手】对已绑定店铺近 30 天商品数据做流量-转化断层诊断，识别三类沉默黑洞。

━━━━━━━━━━━━━━━━━━━━━━━━
【执行前预检】——必须先输出此行：
"本次诊断：在售商品共 X 个，有效数据商品 Y 个（曝光>0），进入三类黑洞扫描。开始执行。"
━━━━━━━━━━━━━━━━━━━━━━━━

【黑洞定义与筛选条件】

🕳️ 黑洞A——"曝光黑洞"（被平台忽视）
条件：近30天搜索曝光 < 全店曝光均值 × 0.3，且商品发布已超过60天
含义：商品长期得不到流量分配，可能是权重问题/关键词覆盖不足/违规降权

🕳️ 黑洞B——"点击黑洞"（买家看了不点）
条件：近30天搜索曝光 ≥ 全店曝光均值 × 0.5（有足够曝光），但点击率 < 全店CTR均值 × 0.6
含义：曝光有但主图/标题无法吸引点击，是典型的视觉/信息问题

🕳️ 黑洞C——"转化黑洞"（买家点了不问）
条件：近30天点击数 ≥ 全店点击均值 × 0.5（有足够点击），但商机数 = 0 且询盘数 = 0
含义：买家进了详情页但没发询盘，价格/详情/MOQ/认证出现断点

━━━━━━━━━━━━━━━━━━━━━━━━
【输出规则（Token控制核心）】

【一、全店转化健康总览】（只输数字）
| 类型 | 商品数 | 占有效商品比 |
| 正常转化商品 | X | X% |
| 黑洞A（曝光黑洞）| X | X% |
| 黑洞B（点击黑洞）| X | X% |
| 黑洞C（转化黑洞）| X | X% |
| 多重黑洞（≥2类同时命中）| X | X% |

全店关键基准线：平均曝光=X | 平均CTR=X% | 平均商机/点击比=X%

【二、黑洞A清单（曝光黑洞）】Top10，按曝光量升序
| 商品ID | 标题前20字 | 曝光量 | 发布天数 | 断层原因(≤20字) | 修复建议(≤20字) |

断层原因参考（选最可能的1条填入）：
关键词覆盖不足 / 属性填写不完整 / 新品权重未激活 / 疑似降权/违规 / 品类冷门

修复建议参考：
补充长尾关键词 / 完善属性项 / 开P4P加曝光 / 检查违规原因 / 评估是否下架重发

【三、黑洞B清单（点击黑洞）】Top10，按CTR升序
| 商品ID | 标题前20字 | 曝光量 | 点击率(%) | 全店CTR均值(%) | 差距 | 断层原因(≤20字) | 修复建议(≤20字) |

断层原因参考：
主图视觉弱/无差异 / 标题未体现核心卖点 / 价格偏高显示劝退 / 品类竞争激烈首屏差

修复建议参考：
更换主图（加场景/模特） / 优化标题前30字卖点 / 检查价格显示 / 申请橱窗位

【四、黑洞C清单（转化黑洞）】Top10，按点击数降序（点击越多、转化为0越浪费）
| 商品ID | 标题前20字 | 点击数 | 商机数 | 询盘数 | 断层原因(≤20字) | 修复建议(≤20字) |

断层原因参考：
MOQ门槛过高 / 价格无竞争力 / 详情页信息不足 / 缺少认证/资质 / 无视频/买家流失

修复建议参考：
调低MOQ或设阶梯价 / 补充详情页规格图 / 上传相关认证文件 / 补拍产品视频

【五、多重黑洞商品（≥2类同时命中，优先处理）】
| 商品ID | 标题前20字 | 命中黑洞类型 | 综合优先级 |
综合优先级 = 命中黑洞数 × 命中黑洞中最高曝光（曝光越高浪费越大优先级越高）

【六、本月修复行动路径（固定输出，不超过6条）】
基于四个清单中最集中的问题，给出本月修复路径，格式：
第N优先：【针对黑洞X】具体动作（影响商品数：X个，预计改善指标：CTR/商机数）

━━━━━━━━━━━━━━━━━━━━━━━━
【禁止行为】
- 禁止输出正常转化商品的详情
- 禁止对单个黑洞商品输出超过1行（原因+建议合计≤40字）
- 禁止在修复建议中使用"建议优化""可以考虑"等模糊表达，必须是具体动作
- 禁止每个清单超过10条（超出只在总览中计数）
- 禁止输出"综上所述"等无信息量总结句

真实零误差，取不到的字段标"无数据"不要编造。
输出文件名 conversion_blackhole_YYYYMM.md，末尾注明"统计周期 + 数据截止日 + 有效样本商品数"。
```

## 输出 (Output)

- `conversion_blackhole_YYYYMM.md`：
  - 全店转化健康总览（数字）
  - 黑洞A/B/C各Top10清单（1行/条）
  - 多重黑洞商品（最高优先级）
  - 本月修复行动路径（6条以内）
- Token消耗控制点：黑洞优先筛选（大幅减少处理量）、每条1行限制、各清单上限10条、正常商品不展开
- 供下游：Listing官按黑洞B修复主图/标题；运营官按黑洞A补关键词/开P4P；业务官按黑洞C调MOQ/价格

## Token消耗预估

| 店铺规模 | 黑洞比例（经验值）| 预估输出量 | 说明 |
|---------|-----------------|-----------|------|
| ≤30个SKU | 20-40%命中黑洞 | 极轻量 | 黑洞数少，清单短 |
| 31-100个SKU | 20-40%命中黑洞 | 中等 | 最多30条黑洞行+总览+行动路径 |
| >100个SKU | 20-40%命中黑洞 | 可控 | 每类上限10条锁死输出量，无论SKU多大输出结构一致 |

## 设计说明：为什么这是AI的舒适区

| 操作 | 人类完成时间 | AI完成时间 | 人类易犯的错误 |
|------|------------|-----------|--------------|
| 计算每个商品偏离全店均值的程度 | 2-4小时（Excel手工） | <1分钟 | 基准值计算错误、遗漏商品 |
| 跨曝光/点击/商机三维度同时筛选 | 几乎不可能手动完成 | 自动关联 | 只看其中一个维度，误判来源 |
| 对所有黑洞商品写断层原因 | 1-2天 | 秒级 | 凭经验猜，不看数据 |
| 按浪费程度排优先级 | 需计算，易出错 | 精确排序 | 按直觉选"看着顺眼的"处理 |

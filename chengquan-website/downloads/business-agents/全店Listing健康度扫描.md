# 指令：全店 Listing 健康度全量扫描

## 目标 (Goal)

批量扫描已绑定店铺全部在售商品的 Listing 质量，从标题、属性、图片、视频、价格五个维度打分，用异常优先原则输出"最需要立即修复的商品优先级清单"，让有限的优化资源集中打在刀刃上。

## 适用范围 (Scope)

- 智能体：运营-Listing优化官、设计-主图详情设计官
- 工作流：流量转化提升工作流（Listing质量节点）

## 是否定时执行 (Schedule)

是 —— 每月 1 日 10:00 执行一次（抓取TOP引流款后运行，优先级排序可交叉参考）。

## 前置 (Prerequisites)

- 插件【国际站生意助手】ACTIVE；具备商品管理/数据参谋查看权限
- 数据参谋 T-2 延迟，点击率等效果数据截止执行日前 2 天
- ⚠️ Token 控制前置声明（写入指令，AI执行前必读）：
  - 本指令采用"漏斗式输出"：只有异常商品展开描述，正常商品仅计入统计数字
  - 每条诊断文字上限 20 字，禁止展开解释
  - 商品数量 > 50 时，自动分批（每批 ≤ 30 个），每批输出异常清单后继续下一批
  - 执行前必须先输出"预检行"再开始扫描

## 最终使用的指令 (Instruction)

```
请调用【国际站生意助手】对已绑定店铺全部在售商品做 Listing 健康度扫描。

━━━━━━━━━━━━━━━━━━━━━━━━
【执行前预检】——必须先输出此行，再开始扫描：
"本次扫描：在售商品共 X 个，分 N 批处理（每批30个），预计输出异常清单。开始执行。"
━━━━━━━━━━━━━━━━━━━━━━━━

【评分维度与扣分规则】（满分100，逐项检查）
每个商品按以下5个维度打分，仅记录扣分项：

① 标题质量（满25分）
- 标题字符数 < 80 或 > 200：-8分
- 未包含品类核心关键词（判断依据：平台标准关键词或同类目Top词）：-10分
- 存在重复词/堆砌：-7分

② 属性完整度（满25分）
- 必填属性（品牌/材质/颜色/规格等）有空缺：每缺1项 -5分，最多-25分
- 自定义属性 < 3 条：-8分

③ 主图与图集（满20分）
- 主图数量 < 6 张：-10分
- 无白底主图：-5分
- 无场景图/模特图：-5分

④ 视频（满15分）
- 无商品视频：-15分
- 有视频但时长 < 15秒：-8分

⑤ 价格设置（满15分）
- 无 FOB 价格或价格为0：-15分
- 仅有单一价格档（无阶梯/MOQ报价）：-8分
- 价格显著偏离同类目区间（高于Top10均值50%以上）：-5分

━━━━━━━━━━━━━━━━━━━━━━━━
【输出规则（Token控制核心）】

原则：异常优先，正常只计数，不展开

① 全店健康度总览（仅输出数字，不展开）
| 健康分段 | 商品数 | 占比 |
| 80-100分（健康） | X | X% |
| 60-79分（待优化） | X | X% |
| 60分以下（紧急修复）| X | X% |
全店平均分：XX分

② 紧急修复清单（< 60分，全部列出）
| 排名 | 商品ID | 标题前20字 | 健康分 | 核心扣分项（≤20字）|
按健康分升序排列，分最低的最优先

③ 待优化清单（60-79分，仅输出Top10最低分）
同上格式，只列10条

④ 本月优化行动建议（固定输出，不超过5条）
结合紧急清单中最集中的扣分维度，给出5条可立即执行的优化动作
格式："【维度】具体动作（影响商品数：X个）"
例：【视频】为无视频的XX款商品补拍15秒以上产品展示视频（影响商品数：23个）

━━━━━━━━━━━━━━━━━━━━━━━━
【禁止行为】
- 禁止逐条解释健康商品的原因
- 禁止对单个商品输出超过1行的描述（诊断文字≤20字）
- 禁止输出"总体来看…""综上所述…"等无信息量的总结句

真实零误差，取不到的字段标"无数据"不要编造。
输出文件名 listing_health_YYYYMM.md，末尾注明"扫描时间 + 商品总数 + 处理批次"。
```

## 输出 (Output)

- `listing_health_YYYYMM.md`：全店健康度总览 + 紧急修复清单（全量）+ 待优化Top10 + 5条行动建议
- Token消耗控制点：异常优先输出、诊断文字≤20字、分批处理、禁止展开健康商品
- 供下游：Listing优化官按优先级排队修复；设计官根据"图片/视频"维度缺口批量出图

## Token消耗预估

| 店铺规模 | 预估输出量 | 说明 |
|---------|-----------|------|
| ≤30个SKU | 轻量 | 单批完成，输出紧凑 |
| 31-100个SKU | 中等 | 2-4批，异常清单为主要输出 |
| >100个SKU | 较大但可控 | 分批机制保证每批不超限，最终汇总仍为结构化表格 |

# 国际站智能教练：逻辑拆解与企业导师 Skill 方案

## 一、结论先行

这个网页真正值得复用的，不是阿里国际站的具体知识，而是一个完整的训练闭环：

```text
知识学习 → 场景选择 → 连续角色扮演 → 多维评分
        → 找出最弱项 → 回到对应知识补课 → 再练一次
```

原网页是“固定内容 + 固定剧本 + 关键词规则打分”的单页训练器，并不是真正接入大模型的智能体。企业通用版应该保留它简单清晰的闭环，同时补上资料治理、蓝图确认、动态 AI、学习记录、安全和内容更新机制。

## 二、原网页的产品逻辑

### 1. 四个一级模块

| 模块 | 用户做什么 | 系统做什么 | 结果 |
|---|---|---|---|
| 知识学习 | 选择学习主题 | 调取主题知识和 FAQ | 学习业务要点与标准回答 |
| 角色扮演 | 选择客户类型并逐轮回答 | 按固定顺序抛出客户问题 | 形成一段训练对话 |
| 评分系统 | 结束演练 | 用关键词、回复长度、问句和风险词打分 | 总分、等级、亮点、短板与建议 |
| 谈单辅导 | 选择客户异议 | 展开心理判断、处理步骤和示范表达 | 得到可直接参考的处理卡片 |

页面内置了：

- 8 个知识主题。
- 6 类客户角色、3 档难度。
- 6 个评分维度、100 分制。
- 14 类常见异议处理卡片。

### 2. 内容与数据结构

网页把所有内容写在一个 HTML 文件中，主要有三组数据：

- 知识数据：主题、章节、常见问题、标准答案。
- 角色数据：客户画像、难度、背景、问题序列、核心顾虑。
- 辅导数据：异议、心理原因、处理步骤、参考表达。

这种方式无需服务器，双击文件即可使用，适合快速演示和内部小范围培训；但所有内容都与页面代码绑在一起，难以审批、更新、追溯和多人维护。

### 3. 角色扮演逻辑

真实逻辑是：

1. 员工选择一个客户角色。
2. 系统展示角色的第一句话。
3. 员工输入回复。
4. 系统不分析回复，直接播放下一条固定客户问题。
5. 所有问题播放完毕后，提示员工结束练习。

因此，它提供的是可重复的标准化剧本，不是客户会根据员工回答改变反应的动态模拟。

### 4. 评分逻辑

网页把员工所有回复合并成一段文字，再做规则匹配：

| 维度 | 权重 | 主要判断 |
|---|---:|---|
| 平台认知准确度 | 25 | 是否提到预设业务词；是否触碰错误或违规表达 |
| 客户需求洞察力 | 20 | 是否命中当前角色的顾虑词；是否主动提问 |
| 价值传递说服力 | 20 | 是否使用数据、案例、具体数字和利益表达 |
| 答疑应变能力 | 15 | 回复轮数；是否覆盖价格、效果、时间、安全等问题 |
| 沟通感染力 | 10 | 回复长度、提问数量和少量口语表达 |
| 信息合规与边界 | 10 | 是否承诺效果、攻击竞品或使用绝对化表达 |

最终按 90、80、70、60 分映射为 S、A、B、C、D。系统会：

- 把得分比例不低于 80% 的维度列为亮点。
- 把得分比例低于 50% 的维度列为待提升项。
- 找出相对最弱维度，给一条补课建议。
- 提供“再练一次”和“回知识库补课”的入口。

## 三、原逻辑里真正有价值的部分

### 1. 从“知道”走向“会做”

知识不是终点，员工必须在一个角色和任务中使用知识。

### 2. 训练标准公开

评分维度和权重提前公开，员工知道企业期望的正确行为。

### 3. 难度分层

不同角色和顾虑让新人从简单情况逐渐过渡到复杂情况。

### 4. 反馈指向补课

评分不是只给一个数字，而是把弱项重新映射到知识模块。

### 5. 高频问题产品化

把业务经验沉淀成：

```text
问题或异议 → 原因判断 → 处理步骤 → 示例表达 → 合规边界
```

这比堆一份长篇培训手册更容易让新人使用。

## 四、原网页不能直接作为企业级智能体的原因

### 1. 不是真正 AI

客户不会根据员工回答动态追问；系统也不理解语义，只执行固定问题序列。

### 2. 关键词评分容易误判

员工堆关键词可能得到高分；正确的同义表达可能被漏掉；“不能保证”也可能因为出现“保证”二字而被错误扣分。

### 3. 知识无法追溯

页面没有记录内容来自哪份制度、谁批准、何时生效、何时应该复核。

### 4. 内容容易过期

价格、规则、数据和承诺全部硬编码，页面中已经存在容易过期或口径不一致的内容风险。本方案只复用了逻辑，没有验证这些行业事实。

### 5. 没有企业学习管理

原网页不保存学习进度、练习次数、薄弱项趋势、复训记录和员工身份。

### 6. 存在安全风险

原网页把员工输入直接拼进 HTML，存在脚本注入风险。企业版必须把用户输入当普通文本处理，并把密钥和敏感数据放在受控服务端。

## 五、企业通用导师智能体的完整逻辑

### 1. 业务层

```text
企业目标
  ↓
目标岗位与关键任务
  ↓
能力地图与可观察行为
  ↓
课程、FAQ、场景、评分、合规红线
  ↓
网页训练与学习记录
  ↓
业务负责人复核和持续更新
```

### 2. 学习层

```text
入门诊断
  → 学习短知识单元
  → 查看优秀示范
  → 进行角色演练
  → 获得有证据的评分
  → 跳转到薄弱模块补课
  → 再次演练
  → 保存学习档案
```

### 3. 内容层

企业导师至少包含六类内容：

1. 学习模块：结论、原因、操作步骤、示例和边界。
2. FAQ：标准答案、适用条件、不能回答的范围和转人工路径。
3. 场景演练：角色、背景、目标、连续挑战、风险点和结束条件。
4. 评分量表：维度、权重、行为锚点、证据、红线和通过线。
5. 导师工具：难题诊断、处理步骤、示范、禁用表达和升级条件。
6. 学习档案：课程完成、演练次数、得分、弱项和复训提醒。

## 六、企业应该准备什么资料

### 1. 八类必备资料

| 类别 | 资料举例 |
|---|---|
| 培训对象与目标 | 岗位说明书、培养计划、绩效指标、上岗标准 |
| 企业与品牌 | 企业介绍、品牌手册、表达规范、禁用词 |
| 产品或服务 | 产品手册、参数、价格、服务说明、合同规则 |
| 岗位流程 | SOP、流程图、检查表、系统操作手册 |
| 高频 FAQ | 客服知识库、工单、群聊整理、新人常见问题 |
| 真实案例 | 脱敏的优秀/失败通话、聊天、邮件、复盘 |
| 评分标准 | 质检表、考试、评分表、认证或补考规则 |
| 合规边界 | 法务意见、数据政策、红线、转人工和升级规则 |

还要提供网页所需的 Logo、主色、口吻、页脚声明、登录、部署和数据保存要求。

### 2. 资料从哪里收集

按以下优先级收集：

1. 已批准的制度、SOP、合同、产品主数据和合规文件。
2. LMS、知识库、CRM、客服工单、质检和授权通话记录。
3. 主管、培训师、金牌员工、产品和法务访谈。
4. 脱敏的优秀与失败业务样本。
5. 官方外部资料，并记录链接与查询日期。

### 3. 收集与治理方法

1. 指定一个项目负责人和各主题内容负责人。
2. 为每份资料分配唯一来源编号。
3. 记录版本、生效日期、批准人、保密级别和可用范围。
4. 对录音做转写、对扫描件做 OCR、对个人信息做脱敏。
5. 标记冲突、过期和缺失内容，不擅自替企业选择口径。
6. 用岗位专家访谈补充文档没有写出来的判断经验。
7. 让业务负责人复核提炼后的知识、答案、场景和评分点。

## 七、必须设置的“蓝图确认门”

企业提供资料后，不应立刻把所有内容写进网页。先输出一份蓝图确认包，包含：

1. 培训对象、目标、范围和不覆盖内容。
2. 已收到资料、权威来源、冲突和缺口。
3. 页面导航和完整用户路径。
4. 能力地图与课程目录。
5. FAQ 分类、演练场景和导师工具清单。
6. 评分维度、权重、通过线和严重错误。
7. 每个核心模块的一小段样稿。
8. 静态、AI 或混合形态，以及登录、部署和数据边界。
9. 待企业决定的问题和上线阻断项。

只有企业明确说“确认，按这版制作”或同等意思，才生成正式网页。“收到”“我看看”“大概可以”都不算确认。

## 八、最终企业网页框架

本次 Skill 的通用网页母版包含六个入口：

| 页面 | 作用 |
|---|---|
| 学习中心 | 课程目录、短知识单元、关键动作、来源与完成状态 |
| 情景演练 | 角色与难度选择、连续对话、结束评分和补课跳转 |
| 评分标准 | 维度、权重、优秀/通过/风险行为锚点 |
| FAQ | 全文搜索、分类、标准答案、适用范围和升级路径 |
| 导师工具 | 难题诊断、操作步骤、示范、禁用表达和转人工 |
| 学习档案 | 完成度、练习次数、历史得分和内容复核信息 |

网页会显式区分“规则预评分”和“AI 语义评分”，避免把演示能力写成已经上线的 AI 能力。

## 九、三种交付形态

### 1. 静态训练器

- 一个 HTML 文件即可运行。
- 固定或分支场景、规则预评分、本机学习记录。
- 适合原型、离线培训和快速验证。

### 2. AI 导师

- 需要企业登录、应用后端、知识检索、模型服务和审计。
- 能动态追问、开放问答和语义评分。
- 不能把模型密钥直接写进网页。

### 3. 混合方案（默认推荐）

- 课程、FAQ、制度和标准答案保持确定性。
- 角色扮演、追问和解释性反馈由服务端 AI 完成。
- 兼顾企业内容可控和练习真实感。

## 十、本次 Skill 已完成的能力

`build-enterprise-training-mentor` 已包含：

- 企业资料准备表。
- 来源台账模板。
- 蓝图确认单。
- 可验证的训练蓝图 JSON 数据模型。
- 蓝图完整性和确认状态校验器。
- 确认后生成单文件培训网页的构建器。
- 学习、演练、评分、FAQ、导师工具和学习档案网页母版。
- 原网页逻辑拆解、资料采集、教学架构和 QA 验收规范。

已完成的实际测试包括：

- 草稿蓝图可以生成明显标识的待确认预览。
- 未确认蓝图会被阻止生成正式版。
- 已确认蓝图可以生成正式 HTML。
- 桌面和手机端无页面横向溢出。
- 情景演练、连续追问、评分、补课和学习记录可用。
- FAQ 搜索与分类正确。
- 用户输入的恶意 HTML 只作为文字显示，不会执行。
- 修正了“不能保证”被误判为违规承诺的问题。
- 浏览器运行无控制台错误。

## 十一、后续使用方式

企业第一次使用这个 Skill 时，可以直接提出：

> 使用 `$build-enterprise-training-mentor`，先指导我们准备新员工培训资料。我们确认蓝图以后，再生成正式培训网页。

之后按“企业填资料 → Skill 形成蓝图 → 企业确认 → Skill 生成网页 → 验收”的顺序执行即可。
